Project 01 · Core Case Study

KnowledgePilot

企业知识库AI助手

面向企业内部知识管理场景，以“可信、可追溯”为核心，验证RAG问答产品从需求定义到MVP验收的完整闭环。

角色AI产品负责人｜个人项目
周期2026.08 — 至今
类型AI SaaS / RAG
用户场景分析PRDMVP设计AI方案验证测试验收
项目链接：Live DemoGitHub Repository
01 · 背景与问题

从“找文件”到“获得可信答案”

制度、产品、入职、售后与流程资料往往散落在不同文档中。传统查询需要找文件、找章节、找关键词，再自行判断答案；通用LLM又缺少私有知识，并存在幻觉与来源不明的问题。

如何让员工快速获得可信、可追溯的企业内部知识答案？
02 · 用户与场景

三类角色，六类高频知识场景

User 普通员工

快速查询制度与业务资料。

Admin 知识管理员

上传、维护与管理企业知识。

Owner 企业负责人

管理知识、用户和权限，了解使用情况。

请假报销新员工入职产品使用售后投诉处理
用户：“出差打车可以报销吗？”
AI：根据差旅制度给出答案，并附可定位的 Citation 来源。
03 · 问题拆解

问题与产品机制一一对应

资料分散→Knowledge Base
关键词搜索效率低→RAG 问答
AI存在幻觉→Citation
文档中没有答案→no_answer 拒答
反馈无法沉淀→Feedback
使用情况不透明→Dashboard
04 · MVP设计

先验证可信问答，而不是堆叠功能

P0 · V1.0

必须验证

知识库、文档上传与处理、RAG问答、Citation、no_answer、Feedback

P1

验证后扩展

Dashboard、权限、多租户

Later

明确暂缓

Department、SSO、Agent、商业化计费

首版优先验证“企业知识是否能够被可靠检索并生成可信答案”，因此没有在早期投入复杂组织架构、Agent和商业化能力。
05 · 核心流程

知识进入、可信回答、反馈迭代

创建知识库→上传文档→文档解析→知识索引→用户提问→RAG检索→LLM生成→Citation→Feedback→产品迭代
06 · 核心页面

每个页面都对应一个用户问题

Dashboard Screenshot Placeholder

Dashboard

解决管理者无法快速了解知识使用情况的问题。

Knowledge Base Placeholder

Knowledge Base

解决多类企业资料缺乏统一归属与管理入口的问题。

Document Management Placeholder

Document Management

AI Chat

Citation

Feedback Placeholder

Feedback

沉淀低质量问答，形成测试集与迭代输入。

07 · AI能力设计

技术选择服务于产品问题

LLM缺少企业私有知识→RAG 补充外部知识
答案依据不透明→Citation 提供来源
资料不足仍强行回答→no_answer 拒答
单一召回不稳定→Hybrid Retrieval / RRF
输出与引用格式波动→Prompt 约束策略

09 · 限制与迭代

主动界定验证边界

当前限制

测试数据规模有限；尚未开展大规模企业真实用户测试；复杂版式覆盖有限；尚未验证商业化成本。

V1.1

扩充RAG测试集、用户反馈分析、Dashboard。

V1.2 / Future

权限、多租户、知识库隔离；之后再考虑Agent、SSO、企业集成与商业化。
